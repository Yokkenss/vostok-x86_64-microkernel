# Iskra x86-64 Vostok ABI draft 0.1

Target name: `x86_64-unknown-vostok`.

This document makes generated code predictable before the backend exists. It is
provisional until Vostok has a stable userspace syscall and process-entry ABI.

## Machine model

- x86-64 long mode;
- little-endian byte order;
- 8-bit bytes;
- two's-complement integers;
- 64-bit pointers, `usize`, and `isize`;
- natural scalar alignment;
- no x86-64 red zone;
- direction flag clear at every call boundary;
- x87, MMX, and SIMD are not generated by compiler version 0.1.

Scalar layout:

| Type | Size | Alignment |
|---|---:|---:|
| `bool`, `u8`, `i8` | 1 | 1 |
| `u16`, `i16` | 2 | 2 |
| `u32`, `i32` | 4 | 4 |
| `u64`, `i64`, `usize`, `isize` | 8 | 8 |
| pointer | 8 | 8 |

A stored `bool` must be the canonical byte value zero or one.

## Function calls

Version 0.1 follows the integer subset of the System V AMD64 calling convention:

- integer and pointer arguments use `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`;
- remaining arguments are placed on the stack;
- scalar return values use `rax`;
- `rbx`, `rbp`, and `r12`–`r15` are callee-saved;
- `rax`, `rcx`, `rdx`, `rsi`, `rdi`, and `r8`–`r11` are caller-saved;
- `rsp` is aligned to 16 bytes immediately before `call`;
- the callee observes `rsp + 8` aligned to 16 bytes on entry.

Structures are not passed or returned by value in version 0.1. Code passes an
explicit pointer to their storage. This avoids implementing the full SysV
aggregate classification algorithm in the bootstrap backend.

## Structure layout

Fields appear in declaration order. Each field begins at the smallest offset
that satisfies its alignment. Structure alignment is the maximum field
alignment, and tail padding makes the total size a multiple of that alignment.

For example:

```text
struct Header {
    kind: u8,     // offset 0
    length: u32,  // offset 4
}                 // size 8, alignment 4
```

Layout is part of the target ABI and must not depend on optimisation level.

## Symbols

- `extern fn` uses the source identifier unchanged as its ELF symbol.
- A non-extern Iskra function uses `_I<decimal-length><name>`.
- `fn tick` therefore becomes `_I4tick`.
- `pub` controls symbol visibility but does not change mangling.

Module-qualified mangling is intentionally postponed until modules exist.

## Process entry

A Vostok executable exports `_start`. The compiler-provided startup stub will:

1. accept the stack supplied by the Vostok ELF loader;
2. establish ABI alignment and clear `rbp`;
3. preserve the two bootstrap capability handles in `rdi` and `rsi` and call
   `_I4main`;
4. pass its `i32` result to the process-exit syscall;
5. trap or halt if the syscall unexpectedly returns.

Programs that need no bootstrap authority use:

```text
pub fn main() -> i32
```

Capability-aware bootstrap programs may instead use:

```text
pub fn main(first_capability: u64, second_capability: u64) -> i32
```

Extra machine arguments are ignored by a zero-argument function under the
calling convention. Initial stack contents beyond the aligned empty stack are
still unspecified.

## Vostok syscall boundary

The target runtime enters Vostok through interrupt vector `0x80`:

| Register | Meaning |
|---|---|
| `rax` | syscall number on entry; result on return |
| `rdi` | argument 1 |
| `rsi` | argument 2 |
| `rdx` | argument 3; received capability on IPC receive |
| `r10` | argument 4 |

The compiler calls ordinary SysV wrapper functions. This keeps the Vostok
syscall convention in the target runtime rather than turning it into a language
semantic. `vostok_ipc_receive(endpoint, out: *mut Message)` writes the received
word and capability to explicit caller-owned storage and returns zero. A
negative kernel error leaves that storage unchanged.

## Object format

The first code-generating compiler emits GNU assembler syntax and delegates
assembly and static ELF64 linking to GNU binutils. Later compiler versions will
emit ELF64 relocatable objects directly, followed by a small Iskra linker.

Dynamic linking, thread-local storage, constructors, destructors, unwinding,
exceptions, and position-independent executables are outside version 0.1.
